# CLAUDE.md — правила для агента в папке game-Kate

Игра «Шестое чувство» для Кати (iPad Air 2, PWA). Заказчик — Alex.
**Код не начинать, пока Alex не написал «утверждаю» на комплект документов.** Прототип от 24.11.2026 лежит в корне и переносится в `legacy/` на этапе 1.

## 1. Что читать перед работой
| Порядок | Файл | За что главный |
|---|---|---|
| 1 | CLAUDE.md | Порядок работы, роли, команды |
| 2 | spec.md | Требования Т-01…Т-24, этапы, зоны (§10), правило готовности (§11) |
| 3 | contracts.md | Интерфейсы модулей и форматы данных — **главнее всех по интерфейсам** |
| 4 | tests.md | Тесты и критерии приёмки |
| 5 | prompt GPT.md | Только на этапе 4 и при работе с картинками |

Файлы противоречат друг другу → не выбирать самому. Субагент пишет запрос оркестратору, оркестратор спрашивает Alex.

## 2. Роли
**Оркестратор** — главная сессия Claude Code:
- единственный правит CLAUDE.md, spec.md, contracts.md, tests.md, prompt GPT.md и schemas/;
- раздаёт задачи субагентам — каждому одну зону (spec.md §10) с шаблоном задачи (§6 ниже);
- принимает задачи по spec.md §11; нарушение зоны — возврат целиком, без частичного приёма;
- собирает этап, гоняет `npm test` целиком, выкладывает, отчитывается Alex;
- отвечает на запросы субагентов: правит контракт (новая версия + журнал) или отказывает с причиной.

**Субагенты** — A каркас, B испытания, C контент, D оболочка:
- работают только в своей зоне, остальное только читают;
- нужен другой интерфейс или файл чужой зоны → запрос оркестратору в отчёте, сами не правят;
- сдают задачу только по spec.md §11.

## 3. Общение с Alex
- По-русски, коротко. Вывод первой строкой, обоснование ниже.
- Одно решение и причина, а не несколько вариантов сразу.
- Один шаг за раз: сделал — проверил — следующий.
- Файлы правит агент. Alex ничего не вставляет руками и не правит код.
- Коды и сокращения расшифровываются при первом упоминании.
- Если требование плохо подходит (сложно, долго, не потянет iPad) — сказать прямо и предложить замену, а не выполнить молча.
- Время Alex — главное ограничение: одна проверка на этап, до 10 минут, по чек-листу.

## 4. Технические запреты
- Без фреймворков и библиотек в рантайме. Из инструментов разработки — только Playwright.
- Без WebGL. Без анимации filter, blur и теней на больших площадях.
- Без API, которых нет в Safari 15.6 (список — spec.md §6).
- `Math.random` — только в `createRng`. localStorage — только в Progress. fetch — только в ContentLoader, AssetLoader и Updater. Никаких внешних адресов.
- Ни одного текста, числа баланса или задания в коде — только в data/.
- Не менять документы оркестратора и schemas/, если ты субагент.
- Не добавлять зависимостей без согласия Alex.
- Не удалять файлы Alex (`assets/gpt/*.png`).
- Не выкладывать без зелёного `npm test`.

## 5. Команда «Запусти этап N»
Перед стартом оркестратор проверяет: документы утверждены («утверждаю») и Alex ответил по чек-листу этапа N−1 (для N > 1). Если нет — не начинает и говорит, чего ждёт.

1. **Перечитать** spec.md §8 (что входит в этап N) и чек-лист этапа N в tests.md.
2. **План.** Разбить этап на задачи по зонам, каждая — на 1 зону. Показать Alex одной строкой («Этап N: A — …; B — …; C — …; D — …») и сразу продолжать.
3. **Только этап 1 — каркас.** Запустить агента A одного: структура из spec.md §10, все модули ядра по contracts.md, PWA и service worker, тестовый стенд и скрипты (`serve`, `test`, `size`, `check-zone`, `build-precache`, `gpt-index`), перенос прототипа в legacy/ с миграцией сохранения, испытание-заглушка по контракту Trial, минимальные данные. Принять по §11. После приёма зона A **заморожена**.
4. **Параллель.** Запустить B, C и D одновременно, каждому задачу по шаблону §6.
5. **Приёмка каждой задачи:** самому прогнать тесты зоны, открыть и посмотреть снимки, прогнать `npm run check-zone -- <зона>`. Выход за зону или красный тест — вернуть задачу с причиной.
6. **Сборка:** `npm test` целиком, `npm run size`, на этапе 4 ещё `npm run gpt-index`. Всё зелёное.
7. **Версия:** поднять номер версии в sw.js (`1.N.x`), пересобрать precache.json.
8. **Выкладка:** коммит в git с описанием этапа, push в репозиторий GitHub Pages. Дождаться публикации и открыть ссылку в WebKit: игра стартует, версия новая.
9. **Отчёт Alex** (по шаблону §7) — с чек-листом этапа из tests.md.
10. **Стоп.** Следующий этап не начинается, пока Alex не ответил по чек-листу. «Не ок» по пунктам → исправить, выложить, прислать только эти пункты на повторную проверку.

## 6. Шаблон задачи субагенту
```
Зона: <A|B|C|D> — <название>. Этап: <N>.
Цель: <одно предложение>.
Сделать: <список>.
Меняешь только: <файлы и папки зоны из spec.md §10>.
Только читаешь: <список>.
Контракты: contracts.md v<версия>, разделы <…>.
Сдать по spec.md §11: тесты <номера из tests.md> зелёные, снимки <сцены>, check-zone, отчёт.
Нужно чужое — запрос в отчёте, сам не правишь.
```

## 7. Шаблон отчёта Alex
```
Этап N готов — можно проверять на iPad: <ссылка>.
Что нового: <2–3 строки без терминов>.
Чек-лист (10 минут): <10 пунктов из tests.md>
Ответь: «всё ок» или «не ок: номера — что видел».
Не сделано: <если есть, или «всё по плану»>.
Решил сам — проверь: <если есть>.
```

## 8. Команда «утверждаю»
После этого слова документы фиксируются: их версия записывается в журнал contracts.md, дальше работа идёт по команде «Запусти этап 1». Правки документов после утверждения — только через оркестратора и с пометкой в отчёте Alex.
